# DESIGN.md — 官网的视觉方向与设计系统

> 这份文件只写**视觉方向与设计系统**；产品事实见 `PRODUCT.md`，两者不混。
> 它和 `PRODUCT.md` 是给改官网的人（和 AI）看的，**不属于部署集合**，不上传服务器。
>
> **为什么要有这份文件**：设计决策不落纸，就会被训练数据的引力拉回"全世界 SaaS 模板长一样"
> 的那一小撮安全模式。落纸之后它还能被检查（见 §8）。
>
> **本文件的元规则**：只写"为什么选 Y"，不写"禁止 X"。禁止清单治不了病——按禁止清单改完，
> 只是把默认值换成了下一代默认值（上一代是紫渐变，这一代是暖米色加衬线斜体）。

## 0. 气质

三个词，每个都可检验：

| 词 | 可检验的含义 |
|---|---|
| **证据感** | 能给真机截图的地方绝不放装饰图；数字必须能核对来源，核对不了就不显示 |
| **工具感** | 这是说明性界面，不是宣传品。排版服务于"扫读定位"，不服务于"看着高级" |
| **校内感** | 面向本校学生的直白表述（"不确定就选 64 位"），不套用商业落地页话术 |

反面定性：**不是 SaaS 落地页**。没有竞品对比、没有定价表、没有注册漏斗、没有社会证明数字。

## 1. 色彩：颜色必须携带信息

现状 token 全在 `style.css` 的 `:root`。对比度用 `tool/contrast.ps1` 实测（vs 白底 `--surface` / vs 页面底 `--bg`）：

| Token | 值 | vs #FFF | vs #F7F7F8 | 允许的角色 |
|---|---|---|---|---|
| `--text` | #171717 | 17.93 | 16.75 | 标题、正文强调 |
| `--text-secondary` | #4B5563 | 7.56 | 7.06 | 正文基线灰 |
| `--text-muted` | #6B7280 | 4.83 | 4.52 | 元信息、注释、提示 |
| `--primary-dark` | #2563EB | 5.17 | 4.83 | 小号主色文字、文字链接 |
| `--danger` | #DC2626 | 4.83 | 4.51 | 错误与风险：文字、图标、边框 |
| `--success-deep` | #047857 | 5.48 | 5.12 | 成功态：文字、绿底按钮、对号图形 |
| `--primary` | #3B82F6 | 3.68 | 3.44 | **仅图形**：按钮底色、描边、图标、≥ 18px 大字 |

两条可执行的下限（`test/website_contract_test.dart` 已经卡住）：

1. `:root` 里每个颜色 token 要么对白底 ≥ 4.5，要么被显式写进测试的 `graphicOnly` 豁免名单。想新增一个文字色，就得先让它达标，不能静悄悄拿 #3B82F6 凑。
2. 任何规则块里同时写了 `color` 与 `background` 的，两者对比不得低于 2.5（防“白字压浅底”这类直接看不见的错）；低于 4.5 的组合全部列在 `weakPairsBaseline` 里，只能越改越短。目前只剩两项：主色按钮白字 3.68（债务 V-10）与图标蓝底 3.38（非文字，满足 3:1）。

语义分工是硬规则，不是偏好：

- **蓝 = 品牌**，唯一主色，`--primary` / `--primary-dark` / `--primary-light(er)` 一组。
- **红绿 = 状态专用**：`--danger` 失败/危险、`--success-deep` 成功。橙黄为警告预留位（当前 `:root` 里没有 `--warning`，需要时再加，加了就必须被 `var()` 使用且达 AA）。
  它们一旦出现在纯装饰位置（比如给“联网检测守护”卡片配个红底图标），用户读到的信息就变成“这里有问题”。
  **一个颜色用于装饰，就必须从语义位移除——不能两栖。**
- **平台色只在需要区分平台时出现**，走 `help.html` 已有的局部变量约定，不要提到 `:root`：
  `#windows { --accent: #2563EB }`、`#android { --accent: #0F9D58 }`、`#ios { --accent: #7C3AED }`，配套 `--accent-soft` 作底色。
  新增平台或新增分区就照抄这个模式。
- **渐变**：允许有语义来源的渐变（平台色带 `linear-gradient(135deg, var(--accent), color-mix(...))`、`install-card` 的浅蓝→浅紫提示"这是 iOS 入口"）。
  判断标准不是"好不好看"，是**这个颜色能不能被指认为某个已知对象**。指认不出来的全屏渐变就是噪声。

## 2. 层级与可读性：四条下限

1. 正文灰度不得低于 `--text-secondary`；元信息用 `--text-muted`。要“轻一点”靠**字号与位置**，不靠把字压灰。
2. 小号主色文字用 `--primary-dark`（5.17）；`--primary` 不做大面积正文（3.44），也不得用在白底按钮文字上（债务 V-10）。
3. 标题不必跟一句更小更灰的副标题。`h1 + .hero-tagline + .hero-desc` 三层灰阶递减是模板反射；
   留着是因为我们确实有话要说——那就要能说清**每一层各自回答什么问题**（H1＝是什么，tagline＝怎么运作，desc＝给谁/凭什么），否则合并成一层。
4. 可点区域 **≥ 44×44px**（触屏）。文字链之外，按钮、标签页、列表项都要用 padding 把热区撑够。

## 3. 尺度

现状是散的：20 种字号（含 14.5 / 17.5 半步）、31 种间距值、10 种裸圆角。定推荐集如下，
**新代码只能从推荐集里选**，选不出来就是设计问题，不要发明中间值。

字号角色（响应式小一档用现成的，不新增值）：

| 角色 | 桌面 | 移动 |
|---|---|---|
| 首屏 H1 | 40 | 28 |
| 区块 H2 | 28 | 22 |
| 卡头 H3 | 18 | 17 |
| 正文 | 15（行高 1.75） | 15 |
| 次要正文 / 列表 | 14（1.7） | 14 |
| 元信息 / 注释 | 13（1.6） | 13 |
| 脚注、校验值 | 12 | 12 |
| 代码 | 13，等宽，`--surface-muted` 底 | 同 |

- **间距刻度**（4 的倍数）：`4 · 8 · 12 · 16 · 24 · 32 · 48 · 80`。
  现存 31 种间距值里的 10 / 14 / 18 / 22 落在 12、16、24 之间，属遗留带（见债务 V-5）；其中 **80 是区块之间唯一的呼吸量**。
- **圆角**：只用 `--radius 8`（按钮/输入）、`--radius-lg 12`（小卡）、`--radius-xl 16`（大卡/弹窗）、`--radius-full`（胶囊）。
- **阴影**：`--shadow-sm` 静止卡面 → `--shadow` hover / 浮起 → `--shadow-lg` 弹窗与 hero 图形。**只三级，不做第四级。**

## 4. 图形与图像

- **真机截图是本站最重要的图形资产**：`help-assets/{windows,android,ios}/`，27 张，命名 `<平台>-<序号>[b]-<语义>.png`
  （`01b` 表示同一屏的续接截图，如长页底部）。宽度类固定三种：`.win`（760）、`.pad`（620）、`.phone`（300）。
  新截图必须被页面引用，孤儿图由测试卡住（白占分发体积）。
- **图标只用同一套**：`viewBox="0 0 24 24"`、`stroke-width="2"`、线性、`currentColor`。填充型只允许 GitHub / Windows / Apple 这类品牌标志。
- 彩色圆角方块 + 图标的组合，**只用于承载"平台"这一层含义**（如下载卡的 `platform-icon`、弹窗选项的 `ico`）。
  给六个功能配六个彩虹色图标不传递任何信息，见债务 V-6。
- 不用假界面图。假的窗口壳（红黄绿三点 + 灰骨架线条）比没有图更糟：它暗示了一个我们不提供的界面。

## 5. 动效：只演"状态变化"，不演"进场"

保留（现有、且都携带信息）：弹窗 `dlgFade .18s` / `dlgUp .2s`、教程切页 `tutFade .28s`、hover 反馈 `0.2s`、截图 hover 上移 2px。

分寸：≤ 0.3s；`transform/opacity` 优先；不做滚动进场、视差、数字滚动、背景流动——**理由不是它们丑，是本站首屏的唯一任务是 3 秒内回答"我该下哪个包"**，而这些动效全都把注意力从任务上挪走，并且拖累首屏渲染。如果将来有信息确实只能靠动画传达（例如演示"连接→认证→守护"的时序），那时该加就加。

无障碍：`prefers-reduced-motion` 下动画必须可整体退化为直接切换（现状待补，见债务 V-7）。

## 6. 决策记录（改之前请先读"为什么"）

- **D-F1 · 字体栈是中文优先**：`"PingFang SC", "Noto Sans CJK SC", -apple-system, "Segoe UI", Roboto`。
  不引入 Web 字体（含 Inter）。理由：正文是中文，拉丁字体对中文字形无能为力，"字体角色"会形同虚设；
  而 Inter 已经是被用滥的默认值。附带收益：零外部字体请求、离线可读、不额外增加首屏关键资源。
- **D-F2 · 内容宽度三档**：首页 1100、教程 1000、工具页（share）720。
  理由：行长控制在约 40 汉字以内，教程与工具页是"照着做"的页面，长行会串行。
- **D-F3 · 教程用编号时间轴**，而不是并排卡片网格。理由：教程是线性流程，**编号是用户"我走到第几步"的唯一坐标**；卡片网格会抹掉顺序。
- **D-F4 · sticky 平台标签页**（`top: 64px`，与导航条高度绑定；移动端导航降到 56px 时同步改）。理由：三平台内容互斥，用户需要随时知道自己看的是哪一栏。
- **D-F5 · 官网不做暗色模式**。App 支持深色（Android 端有深色模式适配），官网不做。理由：说明页第一优先是可读与可打印（有人会截图保存步骤），且不引入一整套需要维护的配色分支。
- **D-F6 · 首页三列网格仅用于"互相独立、无顺序"的内容**（三平台下载卡＝有顺序无关，平权；隐私三卡＝平权）。
  功能特性六卡用三列网格是历史遗留，其含义其实是"一条链：连接 → 认证 → 守护 → 自启"，见债务 V-6。

## 8. 怎么执行

**规则化，而不是靠感觉。** 提示词是软的、这次生效下次失效；规则是硬的，能被检查、被计数、被卡住。

```powershell
flutter test test/website_contract_test.dart   # 结构 / 引用 / 版本一致 / 合规与隐私红线 / 对比与热区 / 棘轮基线
powershell -NoProfile -File tool/contrast.ps1  # 手写色值与 token 的对比度对照
```

`test/website_contract_test.dart` 分三类：

- **绝对断言**（今天就该满足、任何时候破了都是回归）：文件同层、本地引用不 404、无孤儿截图、
  三端版本号与直链一致、备案与免责信息齐全、无统计埋点脚本、敏感页 `noindex` 且零第三方 SDK。
- **可读与可用下限**：颜色 token 要么对白底达 AA 要么被显式豁免；同一规则块里的文字与背景不得低于 2.5（就是它扫出了 `.phase-label .tag` 那个 1.09）；
  已撑够 44px 的选择器不得退化。**覆盖盲区**：扫描器只解 `:root` token，所以 `help.html` 的 `--accent` 局部变量与所有渐变不在检查范围内，得靠人工（见下面清单第 3 条）。
- **棘轮断言**（`只减不增`）：内联 style 数量、字号种类数、裸圆角种类数、`weakPairsBaseline` 里的弱对比组合不得超过文件里记录的基线。
  基线冻结的是**现状**，不是推荐值——修完一条债务就把基线数字往下改，并同步更新 §7。

**上线前的人工验收清单**（自动检查扫干净了只是证据，不是证明；真实渲染出来的体验还得自己看）：

1. iPhone Safari + 小米（HyperOS）+ 一台 32 位旧机，各自看首屏：主按钮文案与目标包对不对？
2. Windows 11 浏览器：下载直链是否真的落地、弹窗三个包是否都在 `/dl/` 里存在。
3. 教程页在横屏矮视口（横放的手机）与 768px 以下：并排截图是否按 §4 的规则堆叠；三平台的 `--accent` 色带与注释条文字实际读不读得清（扫描器不管这块）。
